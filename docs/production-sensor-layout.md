# 前向激光雷达与四相机参考布局

这套配置用于重新采集 CARLA 原生传感器数据。它参考配备前向激光雷达的量产车布局，使用 CARLA 内置 Model 3 作为车身代理；它不是特斯拉原厂配置，也没有声称复刻某款量产车的安装标定。

本版已完成五个完整场景的原生重新采集、处理和来源核对，共 3,901 帧、195.05 秒。成片为 1920×1080、20 fps，详细检查范围见 [公开摘要](media/accepted-production-v4-summary.json)。配置文件为 `carla/sensor-profiles/production-forward-120.json`，实际采用的参数以每次采集保存的 `sensor-profile.json` 和 manifest 为准。

## 位置与覆盖

坐标单位为米，相对于 CARLA 自车原点；x 向前、y 向右、z 向上。旋转字段按 pitch、yaw、roll 排列。

| 传感器 | 参考安装区域 | 位置 x / y / z | 朝向 | 水平视场 |
| --- | --- | --- | --- | ---: |
| 前相机 | 前挡风玻璃上部 | 0.55 / 0 / 1.40 | 向前 | 90° |
| 后相机 | 后车身、牌照区域附近 | −2.45 / 0 / 0.75 | 向后，俯角 4° | 100° |
| 左相机 | 左侧车身外缘 | −0.30 / −1.08 / 1.25 | 向左 | 110° |
| 右相机 | 右侧车身外缘 | −0.30 / 1.08 / 1.25 | 向右 | 110° |
| 激光雷达 | 车顶前部 | 0.45 / 0 / 1.67 | 向前 | 120° |

这些位置已在原生短片中检查遮挡与画面，完整场景也完成了关键帧抽查；抽查不等于人工逐帧审阅。四路相机均为 1280×720、20 Hz，独立保存各自内参和每帧外参。跟车镜头是拍摄机位，不参与感知。

激光雷达的角度参考 [Hesai AT128](https://www.hesaitech.com/product/at128/)：128 线、120° 水平视场和 25.4° 垂直视场。这里采用 CARLA `sensor.lidar.ray_cast`，量程上限设置为 120 米，20 Hz；这些设置不构成对实物扫描时序、噪声、反射率或硬件性能的验证。

CARLA 0.9.16 将扫描角度限制在指定水平视场内。120°、20 Hz、0.05 秒固定步长下，每帧扫描前方 −60° 到 +60° 的扇区。后车不在该 LiDAR 的扫描范围内，不能因为后视图检测到了车辆就生成它的激光点。原生实现见 [RayCastSemanticLidar.cpp](https://github.com/carla-simulator/carla/blob/0.9.16/Unreal/CarlaUE4/Plugins/Carla/Source/Carla/Sensor/RayCastSemanticLidar.cpp#L83-L136)。

返回点以 float32 保存，边缘点在射线碰撞和坐标变换后可能略超出名义角度。校验完整保留原始点，同时记录严格越界数量与最大偏离；工程检查要求边界平面偏离不超过 5 毫米、角度偏离不超过 0.02°，两项必须同时满足，并直接拒绝 x<0 的后向点。这是本项目的开发校验容差，不是已证明的 PhysX 数值误差上界，也不是扩大传感器的名义视场。

本次完整采集中，匝道汇入的三个原生返回和环岛的一个原生返回超过上述开发容差，最大平面偏离约 7.87 毫米、最大角度偏离约 0.02481°。它们都在车前方。普通严格校验的失败保留；独立入口只对这两次采集的四个确切原始点进行限定复核，绑定采集与配置 SHA、原生回调 SHA、帧号、行号和 float32 XYZI 字节。处理时仍扫描所有原始点，任何新增违规、后向点、数据或来源变化均被拒绝。原始点不裁剪、不修正，正常的距离、自车、体素及地面处理仍逐项核对。限定报告明确区分来源与关联几何核对和严格视场失败，不把它写成全部严格通过，也不声称已经找到这些边界偏离的唯一原因。

## 图像与点云处理

`carla/fuse_production_sensors.py` 对四路原生 RGB 分别运行官方 YOLOX-S 预训练模型。原始预测门槛为 0.30；前视展示门槛为 0.75，后视与侧视为 0.50。这是开发配置，不能用这些演示画面宣称检测准确率。

前相机通过真实标定与前向 LiDAR 做几何后融合。只显示有足够实测点支持的距离；距离为观测表面到传感器的距离，不代表完整车身中心。点云俯视图和三维图仅改变显示视角，来源仍是原生返回。

后相机和侧相机目前只做图像检测，不显示激光距离、不分配激光点。四路相机各自保持短时编号，没有跨相机车辆重识别。侧相机部分视场即使与 LiDAR 重叠，这版处理器也尚未利用该重叠做侧向融合。没有毫米波雷达输入，没有假定未安装的传感器或生成不可见区域的数据。

整个流程为录像后的离线处理。车辆继续由原生物理与公开规则控制，识别结果没有回传控制车辆；20 fps 视频播放不等于实时推理。

## 复现入口

在自有 CARLA 0.9.16 服务上，向既有场景录制命令增加：

```powershell
python carla/run_capture_logged.py --log NEW_CAPTURE.log -- --route-json ROUTE.json --map MAP --out NEW_RUNS --fps 20 --width 1280 --height 720 --sensor-profile-json carla/sensor-profiles/production-forward-120.json --chase --rear --instance
python carla/fuse_production_sensors.py --run NEW_RUN --out NEW_FUSION --model MODEL.onnx --threads 3
python production/assemble_production_video.py --help
```

录制器会重新建立传感器、设置原生安装位置和视场，保存配置原文及 SHA。处理器拒绝旧的 360° 点云输入，不通过裁剪旧录像模拟新安装。原始 PNG、LiDAR 点行、frame、timestamp、标定和处理源代码均绑定到结果；检测不使用其他车辆的仿真真值。
